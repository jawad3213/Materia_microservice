# Fargate test environment

A throwaway copy of Materia on **Amazon ECS Fargate**: bring it up, try it, destroy it. It is independent of the
EC2 staging and production environments (its own network, images, secrets and local Terraform state) and needs
nothing from `aws/bootstrap`.

```
internet ──▶ load balancer :80 ──▶ frontend (nginx) ──/api──▶ gateway ──▶ procurement, identity, master data,
             (allowed_cidrs only)                                         finance, analytics ──▶ PostgreSQL, Kafka
```

| Piece | On Fargate |
|---|---|
| Services, gateway, frontend | One ECS service each, one task, in public subnets (no NAT gateway to pay for) |
| PostgreSQL, Kafka | Containers too, on the task's own disk: **their data is lost when the task stops**, and with the environment |
| Finding each other | Cloud Map private DNS: `<service>.materia.internal` |
| Attachment files | An S3 bucket, `procurement/` and `finance/` prefixes, each service's role limited to its own |
| Secrets | Generated by Terraform, in Parameter Store, given to each container that needs them only |
| Logs | CloudWatch, `/ecs/materia-fargate-test`, kept 3 days |
| Access | HTTP on the load balancer, from `allowed_cidrs` only |

## Cost

Roughly **0.30 to 0.35 USD an hour** in eu-west-3 while it runs (about 8 USD a day): the tasks' CPU and memory
(about 4.5 vCPU and 9 GB), the load balancer and the public IPv4 addresses. Destroyed, it costs nothing. Check with
the [AWS Pricing Calculator](https://calculator.aws/) if it matters.

## Bring it up

Needs Terraform >= 1.10, the AWS CLI v2 with credentials for the account, Docker, and Java 21 (the Maven wrapper
builds the services). On Windows, run the scripts from Git Bash.

```bash
cd aws/environments/fargate-test
cp terraform.tfvars.example terraform.tfvars    # set allowed_cidrs to your address
./up.sh
```

`up.sh` builds the services and the frontend, pushes the images (tagged with the git commit), creates everything,
then starts the containers in order: PostgreSQL and Kafka, the services' database users, procurement (whose
migrations create the schemas), the users again, the other services, the gateway and the frontend. The first run
takes about 20 to 30 minutes, most of it the build and the services' first start. It prints the address when done.

`./up.sh --no-build` starts the images already pushed for the current commit.

Close VS Code (or its Java extension) while `up.sh` builds: it rewrites the modules' `target/` directories at the
same time as Maven, which breaks the build.

## Use it

With `spring_profile = "dev"` (the default) the demo accounts and data are there:
`admin@materia.com`, `purchaser@materia.com`, `receiver@materia.com`, with the password from
`terraform output -raw demo_password` (generated, not the local default). With `"prod"` it starts empty.

| Task | Command |
|---|---|
| Follow a service's logs | `aws logs tail /ecs/materia-fargate-test --follow --log-stream-name-prefix identity` |
| A shell in a container | `aws ecs execute-command --cluster materia-fargate-test --task <task id> --container identity --interactive --command sh` (needs the Session Manager plugin) |
| Restart a service | `aws ecs update-service --cluster materia-fargate-test --service identity --force-new-deployment` |
| Attachment files | `aws s3 ls s3://$(terraform output -raw attachments_bucket)/ --recursive` |

After a restart, the dashboard can say some figures are unavailable for a minute: the services are still warming up.

## Destroy it

```bash
./down.sh
```

Terraform lists what it deletes and asks for `yes`: every container, the load balancer, the network, the images,
the attachment files, the secrets and the logs. Nothing is kept.
